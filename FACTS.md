## 2. Layout

- `src/core/`: pure domain. models.py (types; `Dish` and `Part` are what site keeps, `Traits` is vocabulary row, `Snapshot` holds them), diet.py (`judge`: does dish fit a `Household`), matching.py (our `CATEGORIES`, offer word filter, weights, `main_protein`), ranking.py (`dinners`, `varied`, `FLOOR_KR` dinner must save), menu.py (`plan`: week's menu over chain sets, METHOD.md §8), dishes.py (full recipe → `Dish`, the `form` a line asks for), search.py (`parse` bokmål into clauses, `tags` per dinner, `Index` to find), ports.py, errors.py. Stdlib only; tests/test_boundary.py enforces.
- `src/app/queries.py`: read-only queries over snapshot for site, API, CLI (`search`, `tally`, `check`). Search index built once at start-up, ranking on first search needing it (index 0.03 s; search with new word ≤ 9 ms, 2026-10-13).
- `src/app/build.py`: offline use cases: `recipes` (pages), `draft` (vocabulary row per new ingredient name: category, then facts), `filed` (every ingredient's category from vocabulary), `match` (offers), `snapshot` (all), `reprice` (offers only, for `--offers`).
- `src/adapters/`: datasets.py (reads/writes `datasets/`, implements `core.ports.Datasets`), profile.py (profile.yaml with pydantic), schema.py (JSON shape for API and CLI), cli.py, and `web/` (main.py, api.py, params.py for query strings, fmt.py for Norwegian numbers, templates, static).
- `src/pipeline/`: offline only, not in Docker image. matprat.py and godt.py (recipe sources, reading pages via pages.py), tjek.py, jev.py, datasets.py (composition root: `uv run python -m pipeline.datasets`).
- `profile.yaml`: our household and place, for CLI (§5); site and build don't read it. `src/adapters/profile.example.yaml` is template, identical today (tests/test_profile.py).

- matprat's robots.txt disallows `/Services/` (its search API), allows `/oppskrifter/`, so pages read one by one. No crawl delay asked; 16 at a time read 300 pages in 29.5 s, no errors (2026-10-13), so full crawl ~7 minutes. Was 3 at a time, half second apart (~40 minutes).
- godt.no's `__NEXT_DATA__` (`props.pageProps.recipe`) holds each ingredient's name, amount, `maxAmount` («1 - 2 ss») and unit, but no grocery department (build assigns one, METHOD.md §2); minutes before, during, after cooking; portions; rating and votes; tags, where «Middag» marks dinners (1 455 of 3 896, 2026-10-14). Title is `recipe-top`'s, page's h1; JSON-LD's `name` is for search engines («Tomatsuppe - Hjemmelaget, rask og skikkelig god» for «Hjemmelaget tomatsuppe»).
- godt.no's robots.txt asks no crawl delay, shuts out only named AI crawlers (GPTBot, ClaudeBot, CCBot, anthropic-ai, …); matris's user agent not among them. Site behind AWS WAF: 8 pages at a time (~38/s) got 2 681 pages in ~70 s, then `202` with no body and `x-amzn-waf-action: challenge` for other 1 215, still ~5 minutes later (2026-10-14). Build reads 4 pages/s (`PER_SECOND`). 2026-10-14 crawl of all pages (3 896) took 16 minutes; index now dinner list (METHOD.md §7). Challenge counts as failed page; before, build read challenges as pages without recipe and silently lost 820.
